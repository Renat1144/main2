# Локальный запуск WordPress

Проект подготовлен для запуска через Docker Desktop. Репозиторий проекта: `https://github.com/renat1144/main2`.

## Первый запуск

1. Установите и запустите Docker Desktop.
2. Откройте PowerShell в этой папке.
3. Выполните `./local-start.cmd`.
4. Откройте `http://localhost:8080`.

При первом запуске скрипт создаёт базу данных, устанавливает WordPress на русском языке, активирует тему `custom-site-theme`, создаёт главную страницу, страницу мастер-класса и два меню.

## Остановка

Выполните `./local-stop.cmd`. База данных сохраняется в постоянном Docker volume и не удаляется обычной остановкой.

## Редактирование

- Название и логотип: **Внешний вид → Настроить → Свойства сайта**.
- Меню: **Внешний вид → Меню**.
- Секции, тексты, ссылки и изображения главной страницы: **Страницы → Главная** в редакторе Gutenberg.
- Содержимое мастер-класса: **Страницы → Мастер-класс №1** в редакторе Gutenberg.
- Заголовок мастер-класса: редактируется как название страницы.

## Перенос на хостинг

### Публичное превью GitHub Pages

`public-site` содержит только анонимно отрисованные главную и страницу мастер-класса,
а также явный список публичных стилей, скриптов и изображений. Workflow
`.github/workflows/pages.yml` публикует только этот каталог после push в `main`.
База, учётные записи, `.env`, `wp-config.php`, приватные архивы и админка туда не входят.

После правок в WordPress обновить снимок командой `./script-public-export.ps1`
при работающем сайте `http://localhost:8080`, проверить diff и отправить его в Git.
GitHub Pages — статическое превью, не WordPress-хостинг: админка, серверная отправка
форм и платежи в нём не работают. Редактирование продолжать в локальном WordPress.
Стартовые тексты темы синхронизированы с утверждённой биографией; существующие
страницы базы при обновлении файлов не перезаписываются.

Для публикации нужны файлы WordPress, включая `wp-content/themes/custom-site-theme`, а также экспорт локальной базы данных и загруженные через админ-панель файлы из `wp-content/uploads`. Секреты из `.env` на хостинг не копируются — на сервере используются отдельные доступы к базе данных.

## Продолжение работы на другом устройстве

Используйте `FINISH_WORK.cmd/.command` на исходном устройстве и
`START_WORK.cmd/.command` на принимающем. Подробная безопасная процедура,
структура приватного ZIP и ручные команды описаны в `LOCAL-TRANSFER.md`.
Штатная папка переноса в Google Drive — `Codex Drive`; на текущем Windows-компьютере
она находится по пути `G:\Мой диск\Codex Drive`.
